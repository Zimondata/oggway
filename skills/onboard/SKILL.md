# Onboarding skill

The bot does not ship with personality. Personality is generated for each new user through a short conversation. This makes the agent generic out of the box and tailored after onboarding, without ever shipping someone else's persona files.

## When to run

- Right after `/setup` finished and `groups/<name>/` exists but contains no `persona.md`
- User says "onboard me" / "represent yourself" / "set up new agent" / "let's start fresh"
- A group has only the default `groups/_skeleton/` content copied in

## Principle

Hermes-style: ask, do not template. Static template files (SOUL.md, USER.md, IDENTITY.md frozen at install time) go stale and ship a stranger's voice. A 2-minute onboarding chat produces persona that fits THIS user.

The skill writes 4 files inside `groups/<name>/`:
- `persona.md` - bot identity (name, tone, hard rules from this user)
- `user.md` - facts about the human (name, timezone, language, what they want from the bot)
- `channel.md` - active channel(s), trigger pattern, response style for each
- `boot.md` - one-line pointers to the shared rule files

Everything else (factuality rule, output format rule, autonomy ladder, memory protocol) stays in `groups/global/CLAUDE.md` - shared across all groups, not duplicated per user.

## Sequence

Use `AskUserQuestion` for every step. Do not assume answers. Do not write files until the final confirmation step.

### Q1. How should I call you?

`AskUserQuestion`: "How should I address you in chat? (your name or handle)"

Free text. Store as `USER_NAME`.

### Q2. How should you call me?

`AskUserQuestion`: "Pick a name for me, or describe the vibe and I will suggest."
Options:
- Type a name (free text)
- "Suggest 3 names based on vibe" -> ask follow-up about vibe, then propose

Store as `AGENT_NAME`. This is what shows in chat replies AND becomes the trigger pattern.

### Q3. Tone

`AskUserQuestion`: "What tone should I default to?"
Options:
- Dry sarcasm, minimal warmth
- Friendly, conversational
- Strictly professional, no banter
- Match how you talk to me (mirror tone)
- Other (free text)

Store as `TONE`. Map to 2-3 sentence persona descriptor.

### Q4. Main language

`AskUserQuestion`: "Default reply language?"
Options:
- Match what you write in (auto-detect each message)
- English always
- Russian always
- Other (free text)

Store as `LANGUAGE`.

### Q5. Hard rules from you

`AskUserQuestion`: "Any hard rules I must never violate? (skip if none come to mind right now, you can add later)"
Free text. Examples to show in question hint: "no emoji", "no em-dash", "never auto-send messages to other people", "always ask before spending money".

Store as `HARD_RULES`. If empty, skip the section in `persona.md`.

### Q6. Memory mode

`AskUserQuestion`: "How should I remember things between sessions?"
Options:
- Local markdown files in `memory/` (default, no setup)
- Connect to my Obsidian vault (I tell you the path)
- Both (vault is primary content, memory is operational state)
- No long-term memory yet (decide later)

If Obsidian is chosen, follow up: "Vault path?" - free text. Validate the path exists. Store as `VAULT_PATH`.

### Q7. Confirm

Show a summary panel built from the answers:

```
Name: <USER_NAME>
Bot: <AGENT_NAME>
Tone: <TONE>
Language: <LANGUAGE>
Hard rules: <HARD_RULES or "none yet">
Memory: <MEMORY_MODE> [vault: <VAULT_PATH>]
```

`AskUserQuestion`: "All correct?"
- Yes, write the files
- Change something -> jump back to the relevant question

## Files to write

Path: `groups/<name>/` (the current group folder, derived from the running context).

### `persona.md`

```markdown
# <AGENT_NAME>

Generated by /onboard on <YYYY-MM-DD> for <USER_NAME>.

## Identity
You are <AGENT_NAME>, a persistent assistant for <USER_NAME>. You run on ClaudeClaw, the agent never forgets between sessions, and you are written to by the user through <CHANNEL>.

## Tone
<TONE descriptor expanded into 2-3 sentences>

## Default language
<LANGUAGE>. <If "match" - rule about mirroring>.

## Hard rules
<HARD_RULES bullet list, or omit section>

## What you are NOT
- Not a generic chatbot. You remember, you decide, you act.
- Not a yes-man. Push back if the user is wrong, with evidence.
- Not a stranger. After a week of use you should know <USER_NAME> better than most colleagues do.
```

### `user.md`

```markdown
# About <USER_NAME>

Generated by /onboard on <YYYY-MM-DD>.

- Name: <USER_NAME>
- Timezone: <auto-detect from system, ask to confirm>
- Default language: <LANGUAGE>
- Main channel: <CHANNEL>

Add facts here as you learn them. Append-only. If a fact changes, strike the old line, add the new one underneath. Never silently rewrite history.
```

### `channel.md`

```markdown
# Channel: <CHANNEL>

- Trigger pattern: @<AGENT_NAME> (set during /setup)
- Reply style: <one line based on TONE>
- Threads: auto-create on first @mention, follow-ups in thread need no trigger
```

### `boot.md`

```markdown
# Boot pointers

This file is the first thing the agent reads. It just points to the shared and per-user rules so nothing gets out of date.

1. Shared rules: `groups/global/CLAUDE.md` (factuality, format, autonomy - same for every group)
2. Your persona: `groups/<name>/persona.md`
3. Who you serve: `groups/<name>/user.md`
4. How you reach them: `groups/<name>/channel.md`
5. Long-term memory: `groups/<name>/MEMORY.md` (curated, only in main session)
6. Daily logs: `groups/<name>/memory/<YYYY-MM-DD>.md` (append-only)

Read in this order on first message of every session. Stop loading once context covers the user's question.
```

## Hard guarantees

- Never write more than these 4 files in one run. Anything else the user asks for during onboarding becomes a follow-up todo.
- Never copy in a persona from another group. Every onboarding starts blank.
- Never skip Q1 or Q2 (those answers control everything else).
- After writing, restart the service so the new files are picked up: `restart_service(reason="onboarded new group <name>", rebuild=false)`.
- Print a one-line success message in chat: "Done. I'm <AGENT_NAME>, you're <USER_NAME>. Talk to me." - nothing more.

## Failure modes

- User abandons mid-conversation -> save partial answers to `groups/<name>/onboarding-draft.json`, resume on next "continue onboarding"
- User picks a name that conflicts with another group's `AGENT_NAME` in the same instance -> warn, ask to pick another
- `VAULT_PATH` does not exist -> ask again, do not silently skip; without a real path the vault tools will all fail

## After onboarding

Optional next-steps to mention once (do not run them):
- "Connect Obsidian: run `/install obsidian-bridge`"
- "Add more channels: run `/add-slack`, `/add-discord`, `/add-whatsapp`"
- "Switch model provider: edit `.env` -> `MODEL_PROVIDER=openrouter` (default: anthropic)"
